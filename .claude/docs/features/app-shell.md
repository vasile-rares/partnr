# The app shell (sidebar, menus, theme)

Plan of the redesign: [ui-redesign.md](../ui-redesign.md). Where `/` sends someone and the workspace pages: [workspaces.md](workspaces.md).

## Web app

- **App shell** (`src/components/shell/`): every signed-in page sits in a sidebar. `AppShell` (server) loads the user, the workspaces they work in and the ones they are a client of, and renders `AppSidebar` (client: it needs `usePathname`, so it only receives serializable data, `ShellContext` in `types.ts`). Two layouts feed it: `app/w/[workspaceId]/layout.tsx` (`kind: "workspace"`, with up to 5 Active projects; for a client, who opens the same address, the client's menu instead, `kind: "client"`, with the projects shared with them) and `app/(shell)/layout.tsx` (`kind: "none"`: `/account`, `/workspaces`, `/workspaces/new`).
- The menus are in `nav.ts`: an item without `href` is a future feature and shows disabled with a "Soon" badge, so turning one on means giving it an `href`. `ContextSwitcher` (workspaces / "Client of") is the sidebar header, `NavUser` (Account, Theme, Sign out) the footer.
- `Page.tsx`: top bar with the sidebar toggle and breadcrumb and, on the right, the `NotificationsBell` (see [notifications.md](notifications.md)), then the content column; `narrow` for forms.
- Dark is the default theme (`theme-provider.tsx`).
- **Skip link and bar colour**: `AppShell` starts with a "Skip to content" link (visible only on keyboard focus) that moves focus to the `<main>` (`id="main-content"`). Each page's `<h1>` lives in its view component, not in `Page`. `ThemeColor` (root layout) keeps `<meta name="theme-color">` equal to the `--background` of the theme in use, for the browser bar on phones; the hex values are in `theme-color.tsx` and must follow `globals.css`.
- **Loading**: `loading.tsx` in `app/w/[workspaceId]/`, its `settings/` and `app/(shell)/` show `PageSkeleton` (`components/layout/`: the same top bar and column as `Page`, grey blocks inside) while a page's data loads; `narrow` matches `Page`'s. A new route that looks very different from a list can get its own `loading.tsx`.
- **Errors**: `error.tsx` in `app/`, `app/w/[workspaceId]/` and `app/(shell)/` render `ErrorState` ("Try again" calls Next's `retry`); the last two keep the sidebar (they wrap it in `Page`). `app/global-error.tsx` is the last resort, with its own `<html>`. Expected failures (a form, a row action) stay inline next to what failed, through `FormError` / the list's `message`.
- **Toasts** (`sonner`, `<Toaster />` in the root layout, bottom right): a short confirmation after a mutation whose result is not otherwise visible (archive, delete, upload, share). The row actions of the project lists get theirs from `toastDone(noun, method, path)` (`lib/toast.ts`), which reads the verb from the last segment of the path sent to `run`; other places call `toast.success(...)` themselves. Errors are not toasts.
- In e2e tests the sidebar's links are under `mainNav(page)` and the breadcrumb under `breadcrumb(page)` (`e2e/helpers.ts`); project names also appear in the sidebar, so look for links inside `getByRole("main")`.
