# Dashboard and calendar

Neither has an endpoint of its own: both are built from the lists the API already gives.

## Dashboard

- `app/w/[workspaceId]/page.tsx`, blocks in `src/components/dashboard/`, rules in `src/lib/dashboard/deadlines.ts`.
- "Needs your attention" (projects with `approvals` to act on or wait for, changes requested first), "Coming up" (deadlines of projects and unfinished stages within 14 days, plus late ones), "Active projects", "Waiting on clients" (invitation sent or expired); a workspace with no projects sees `GettingStarted` instead.
- Built from `getProjects` and `getClients`.

## Calendar

- `app/w/[workspaceId]/calendar/` for both sides (`FirmCalendarView` for a member, `ClientCalendarView` for a client, chosen by the workspace's role), both on `CalendarView` in `src/components/calendar/`, rules in `src/lib/calendar/calendar.ts`, pure and tested without a browser in `e2e/calendar.spec.ts` and `e2e/meetings.spec.ts`.
- The calendar is ReUI's **event calendar** (`src/components/reui/event-calendar/`, installed from `@reui/event-calendar`; the look of its `c-event-calendar-1` example without the demo's settings popover): its own nav (Today, Previous / Next, the view switcher, the title) and the views Month (the default; Agenda on a phone), Week, Day and Agenda, Monday first, 24-hour times. It is the **meetings' page** (there is no Meetings page; see [meetings.md](meetings.md)): it shows every meeting, the ones called off included (greyed, "(cancelled)"), and the **project deadlines and unfinished stages only when "Show deadlines" is ticked** (a checkbox above the calendar, off by default and not remembered), built from `getProjects` / `getClientProjects(workspaceId)` / `getMeetings` / `getClientMeetings`. A member also has **New meeting** in the page header and the Google notice. The calendar is read-only: no dragging, resizing or creating on the grid (`interactions` are off, every event is `readOnly`); a click on a meeting opens its dialog, a click on a deadline goes to its project.
- The month in the address (`?month=2026-11`) is only the month the calendar **opens on**; paging inside it does not change the address.
- `CalendarView` is a client component because the calendar draws in the reader's time zone, which the server cannot know: until the browser has taken over (`useInBrowser`) there is a skeleton of the same height, so nothing the server sent can differ from the first browser render. A deadline is a whole day in the reader's zone (an all-day event), a meeting is the instant it is.
- **A stage covers the days it has on the project's timeline** (`stageSpans` in `lib/calendar/calendar.ts`, from `buildTimeline`): from the day after the previous stage ends (the first, from the project's start) to its own end, the last one reaching the project's end; a stage that is done still marks where the next one starts, one with no date has no event. Without a start date on the project the stages have no span and each is its own day. The project's own end stays a single day. The ReUI calendar draws such an event as one bar across the days (one element per week row in the month grid), and a day with more events than the cell fits shows "+N more". Colours tell the kinds apart (project deadline blue, stage teal, meeting violet, late red).
- An event's name (and so its accessible name, `"<name>, All day"` or `"<name>, 10:30 - 11:15"`) is the project's name for its deadline, `"Project: Stage"` for a stage and the title for a meeting; a late deadline gets " (overdue)" and a called off meeting " (cancelled)".
- In e2e tests the title is `calendarTitle(page)`, deadlines are switched on with `showDeadlines(page)`, and an event is a button inside `getByRole("main")`; `expectOnCalendarDay(page, event, "YYYY-MM-DD", "YYYY-MM-DD")` checks it covers those days of the month grid, and not the one before or after (one date for a single day; an event over several weeks is several elements, so use `.first()` to click it). Use far-off months (2099-01, 2099-07, 2020-03) so the result does not depend on today.
