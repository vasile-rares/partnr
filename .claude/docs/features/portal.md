# The client's side: invitations and the portal

There is no separate portal in the API or in the addresses: a client uses the same `/api/workspaces/{id}/...` routes and the same `/w/{id}/...` pages as the firm, and each gets its own shape and screen (decisions: `decisions.md`, "Portal unificat"). Who may open what is an authorization rule, so it stays in `backend/CLAUDE.md` ("Authorization").

## Web app

- `/invite/[token]` (in `src/app/(auth)/`, public, listed in the `proxy.ts` matcher exclusions) opens an invitation.
- A client belongs to each firm separately: after accepting an invitation, or from `/`, they land on that firm's Home, `/w/{workspaceId}`; the sidebar's switcher lists the others under "Client of". `app/w/[workspaceId]/layout.tsx` answers 404 for a firm the person is neither a member nor a client of.
- `/w/[workspaceId]` shows a client `ClientHomeView` (a member gets the dashboard, `FirmHomeView`): a welcome line, "Waiting for you" with a link per deliverable to the project's Deliverables tab, "Active projects" with `standing`'s Right now / Up next, "Latest updates" across the firm's projects and the next meeting; it loads every project's details with `getClientProjects(workspaceId)` (the summaries, then each project in parallel).
- `/w/[workspaceId]/projects` lists its projects to a client (`ClientProjectsView`, `ClientProjectList`; `getClientProjectSummaries(workspaceId)` in `src/lib/projects/server.ts`). The same address shows a member the firm's list (`FirmProjectsView`).
- `/w/[workspaceId]/projects/[projectId]` is one project to a client (`ClientProjectView`, `getClientProject(workspaceId, projectId)`; the API answers 404 for a project of another firm; a member gets `FirmProjectView` there), on `ProjectTabs` (shared with the freelancer's page; it takes the list of tabs): Overview (description, progress, the three latest updates, stages), Deliverables (hidden while none is shared; its tab badge counts the ones waiting for the client), Updates (the five latest open, the rest in a `<details>`) and Files (hidden while none is shared; `ClientFileList`, download links to `/api/workspaces/{id}/projects/{projectId}/files/{fileId}/download`). In e2e tests click the tab first (`openTab(page, "Updates")`).
- A project that waits for the client's answer shows a "Waiting for you" banner on Overview (`awaitingApproval`, its button opens Deliverables), and the projects list a "N waiting for you" badge.
- Each deliverable carries `ClientApprovalPanel` (`src/components/deliverables/`, listed by `ClientDeliverableList`): the freelancer's note, "Approve" (behind a confirmation, the answer is final) and "Request changes" (a message is required), and the earlier answers in a `<details>` (the wording of Right now / Up next is in `src/lib/projects/summary.ts`); it posts to the workspace's route, `/api/workspaces/{id}/projects/{projectId}/deliverables/{deliverableId}/approvals/{approvalId}/approve|request-changes`.
